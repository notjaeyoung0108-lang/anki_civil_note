# 공부노트 — 정리 · 암기 · 오답

`study/tools/build_review.py` 가 뽑는다. 화면이 셋이고 아래 탭으로 오간다.

| 탭 | 무엇 |
|---|---|
| **정리노트** | 과목 → 장 → 절. **읽는 곳** (빈칸 없음) |
| **암기노트** | 절 하나가 카드 하나. 앞면 = 장·절 이름 / 뒷면 = 뼈대 / 풀이 = 연결 |
| **오답노트** | 노션에 모은 4지선다. 골라서 바로 채점 |

```powershell
py study/tools/fetch_problems.py       # 노션 문제를 먼저 받아두고 (오답노트가 쓴다)
py study/tools/build_review.py         # 노트를 고쳤으면 다시 뽑는다 (3분쯤)
py study/tools/build_review.py --hub-only   # 화면만 손봤으면 (10초)
node study/tools/_check_app.js          # 화면 흐름 점검 (브라우저 없이)
py study/tools/_check_align.py         # 숫자·제목 세로 정렬 실측 (헤드리스 크롬)
```

**암기노트는 2주 한 바퀴다.** 월~금에 한 장씩, 첫 주가 1~5장 다음 주가 6~10장.
그날 배정된 장 + 밀린 것(몰랐어요 → 내일 · 헷갈려요 → 사흘 뒤)이 오늘의 덱이다.
주말이거나 그날 몫을 끝냈으면 **2주 표의 줄을 눌러** 아무 장이나 지금 볼 수 있다.

**오답노트는 틀리면 내일, 맞으면 7일 → 그다음부터 14일**이다. 보기 순서는 볼 때마다 섞는다.

- `index.html` — 세 탭이 다 여기 들어 있다. 카드도 문제도 이 한 파일 안에 굽혀 있다.
- `n-<해시>.html` — 정리노트 한 편. 자체완결(서버·CDN 불필요).
- `q-<id>.webp` — 오답노트 문제의 교재 원본 크롭 (`교재 원본 보기` 토글 뒤).
  이름은 노션 페이지 id 다.

> **노트 파일 이름은 ASCII 해시**다 — 한글 파일명은 브라우저·웹서버·GitHub Pages·윈도
> 로케일 어디서든 한 번씩 어긋난다(URL 인코딩, NFC/NFD 정규화, Jekyll 처리). 이름은 단원
> 경로에서 만들어 고정이므로 다시 뽑아도 같은 파일에 덮인다. 어느 단원인지는 목록에서 본다.
- `.nojekyll` — GitHub Pages 가 Jekyll 처리를 건너뛰게 하는 빈 파일.
- `manifest.webmanifest` · `icon-192.png` · `icon-512.png` · `sw.js` — 홈 화면에 얹어
  **앱처럼** 쓰기 위한 껍데기. 주소창 없이 전체화면으로 뜨고, 오프라인에서도 열린다.

## 앱으로 얹기

- **폰** — 사이트를 열고 공유 → `홈 화면에 추가`. 아이콘으로 들어가면 브라우저 껍데기 없이
  앱처럼 뜬다(`display: standalone`).
- **PC 크롬** — 주소창 오른쪽 설치 아이콘 → `설치`. 별도 창으로 열린다.
- 서비스워커가 모든 페이지를 미리 받아두므로 **비행기 모드에서도** 복습된다.
  (`file://` 로 직접 열 때는 서비스워커가 안 돌지만 페이지 자체는 자체완결이라 그냥 열린다.)

> **캐시 문제는 빌드 번호로 막았다.** 다시 뽑을 때마다 파일 mtime 으로 8자리 번호를 만들어
> 링크(`…html?v=9ffe9d52`)와 서비스워커 캐시 이름에 붙인다. 그래서 새로 뽑으면 브라우저가
> 옛 파일을 붙들 수 없다. 그래도 이상하면 `Ctrl+Shift+R`.
>
> 서비스워커는 **캐시부터** 내주므로, 새 빌드를 올려도 워커가 교체되는 그 한 번은 옛 화면이
> 그려진다. 그래서 새 워커가 자리를 잡는 순간 **딱 한 번 알아서 새로 그린다**(`controllerchange`).
> 새로고침 한 번이면 새 화면이 온다.
>
> **내가 지금 어느 빌드를 보고 있나** — `설정` 화면 맨 아래 `빌드 <날짜 시각 UTC>`.
> 고친 게 안 보이면 여기부터 본다. 시각이 그대로면 아직 안 올라간 것이고, 바뀌었는데도
> 화면이 그대로면 그때 캐시를 의심한다.

## 쓰는 법 — 정리노트

단원 페이지는 **읽는 판**이다. 빈칸이 없다. 제목을 누르면 그 절이 접혔다 펴진다
(`Esc` = 전부 닫기). 처음 배울 때는 강의노트, 매일은 이 정리노트.

> **빈칸을 없앴다 (2026-08).** 문장마다 뚫린 빈칸을 다 외우려 들면 절 하나에서 스무 번을
> 멈추게 되고, 그러다 보면 흐름을 읽는 게 아니라 빈칸 사이를 뛰어다니게 된다.
> 외울 것은 **뼈대와 연결** 둘로 줄였고, 그 둘은 암기노트가 묻는다.

절마다 점 하나로 상태를 보인다 — **아직 / 흔들림 / 익힘 / 굳음**. 그 절의 **암기카드**
연속 정답 수에서 나온다(0 / 1~2 / 3 이상). 2주 한 바퀴이므로 '굳음' 은 한 달 반을 안
틀렸다는 뜻이다.

## 쓰는 법 — 암기노트

```
앞면   제1장 측량학 개론  /  1. 측량의 정의 및 분류
뒷면   [1] 측량의 정의와 3요소   (1) 측량의 정의 — 두 벌  (2) 측량의 3요소  (3) …
       [2] 평면측량과 대지측량   (1) 구분의 기준 …
풀이   한 줄 → 목적 → 연결 → 자가점검
```

절 이름만 보고 **그 안에 무엇이 몇 개 있는지**를 떠올린 뒤 뒤집는다. 맞았는지 틀렸는지는
스스로 채점한다. 왜 그 순서인지 흐릿하면 `풀이 ›` 로 **연결**을 읽는다.

- **표·수치·공식은 카드에 없다.** 그것들은 정리노트를 읽어 채우는 것이지 카드로 외울 게 아니다.
- 카드는 **자동으로 뽑힌다** — 정리노트의 제목·소제목(뼈대)과 개요(연결)가 그대로 카드다.
  노트를 고치고 다시 빌드하면 카드도 따라 바뀐다.
- **번호는 1부터다.** 노트에서는 개요가 `[1]` 이라 개념이 `[2]` 부터인데, 카드에 개요가
  없으니 다시 붙인다. `연결` 이 부르는 번호도 같이 옮겨져서 뒷면 뼈대와 그대로 이어진다.
- **덱 순서는 섞인다.** 과목·장 순서대로 나오면 다음이 무엇인지 알고 뒤집게 되어 인출이
  아니라 확인이 된다. 덱을 짤 때 한 번만 섞고 그 뒤로는 유지한다 — 채점할 때마다 다시
  섞이면 어디까지 했는지 알 수 없다. 오답노트의 문제 순서도 같다.

**2주 한 바퀴**

| | 월 | 화 | 수 | 목 | 금 | 토·일 |
|---|---|---|---|---|---|---|
| 첫 주 | 1장 | 2장 | 3장 | 4장 | 5장 | 쉼 |
| 다음 주 | 6장 | 7장 | 8장 | 9장 | 10장 | 쉼 |

오늘의 덱 = **그날 배정된 장** + **밀린 것**. 오늘 자리가 비면 **안 본 카드**로 흘러간다.
`· 덱` 을 눌러 들어가면 2주 표가 있고, 줄을 누르면 그 장을 지금 볼 수 있다.

채점은 셋:

| | 다음에 언제 | 단추 색 | 글자 색 | 대비 |
|---|---|---|---|---|
| **몰랐어요** | 내일 | `#eb8d8d` | `#ba1a1a` | 2.7:1 |
| **헷갈려요** | 사흘 뒤 | `#D3D3D3` | `#1e242b` | 10.5:1 |
| **맞혔어요** | 그 장이 돌아오는 날 (최대 14일) | `#94d197` | `#118c17` | 2.5:1 |

> 색은 **테마에 따라 바뀌지 않는다** — 어두운 화면에서 빨강·초록이 뒤집히면 뜻이 흔들린다.
> 글자를 흰색으로 두지 않은 이유도 같다: 셋이 비슷해 보이면 손이 기억하는 것이 '자리' 뿐이 된다.
>
> ⚠ 빨강·초록 쌍의 대비가 **WCAG AA(4.5:1)에 못 미친다.** 사용자가 고른 색이므로 그대로
> 두었다 — 흐리게 보이면 **글자색만** 더 진하게 내려라(배경은 그대로).
> `#ba1a1a` → `#8f1414` 면 4.0, `#118c17` → `#0b6410` 이면 4.2 쯤 된다.

### 카드의 생김새

- **그림자**가 있다(`--shadow`) — 손으로 넘기는 한 장이라는 감각을 준다.
- 글자 위계 — 앞면 절 이름 29px · 뒷면 절 이름 22px · `[n]` 제목 18px · 소제목 15.5px.
- 제목 번호는 **각진 검정 네모**다. 둥글리면 그 아래 `(1) (2)` 목록과 무게가 비슷해져
  어느 쪽이 상위인지 눈에 안 온다. 숫자는 14px 이고, 상자가 커지지 않게 `line-height` 를
  1.15 로 조여 20px 안팎으로 잡았다.
- 소제목 번호는 노트와 같은 표기 — `1.` 이 아니라 **`(1)`** (CSS 카운터).
- **풀이의 내용은 Pretendard** 다. 앱에서 가장 긴 산문(연결)이 여기라, 손글씨체로 문단을
  읽으면 눈이 빨리 지친다.

> **서체 셋을 각자의 일로 갈랐다.**
>
> | 서체 | 어디에 |
> |---|---|
> | **주아체**(BMJUA) | 장·절 이름, `[n]` 제목, 소제목 — 짧은 단서 |
> | **이서윤체**(LeeSeoyun) | 정리노트 본문 |
> | **Pretendard Medium** | 풀이(연결) · 오답의 문제·보기·해설 — 길게 읽는 글 |
>
> ⚠ **수식(MathML)에는 Pretendard 를 태우지 않는다** — 서체를 바꾸면 그리스문자·프라임의
> 모양과 자리가 흔들린다. 되돌리는 규칙이 CSS 에서 **뒤에** 와야 이긴다.
  풀이 제목은 `연결 — …` 이 아니라 **절 이름 그대로**다.

> **⚠ 네모칸·제목·배지의 세로 정렬은 실측한 고정 보정값이다.** 주아체는 글리프가 em 박스
> 위쪽에 붙어 있어 `line-height` 로 맞춰도 떠 보인다. 네 자리를 보정한다 —
> `.bh i > span` `0.125em` · `.bh > span` `0.105em` · `#tabs a .n` `-1.12px`
> (알약이 탭 라벨보다 내려가 보인다) · `#tabs .n > span` `0.75px` (알약 안 숫자).
> 그래서 **숫자를 한 겹 감싼다**(`<i><span>2</span></i>`) — 상자 자체를 움직이면 테두리가
> 같이 밀린다.
>
> 글자 크기나 네모칸 여백을 고쳤으면 **`py study/tools/_check_align.py`** 로 다시 재라
> (헤드리스 크롬에 그려 픽셀로 잰다). 캔버스로 매번 재는 방식은 서체 로드 전 값이 캐시에
> 박혀 5px 씩 밀리는 사고가 있었다 — 돌아가지 마라.

키보드: `1`·`2`·`3` 채점 · `Space`/`Enter` 뒤집기 · `Esc` 풀이 닫기.

## 쓰는 법 — 오답노트

노션에 모아둔 4지선다를 그대로 푼다. 보기를 누르면 **바로 채점**되고 해설이 열린다.

- **틀리면 내일 · 맞으면 7일 → 그다음부터 14일.**
- 보기 순서는 **볼 때마다 섞는다** — 자리로 답을 외우는 것을 막는다.
- 카드처럼 **그림자**가 있고, **문제·보기·해설 전부 Pretendard** 다 (수식은 제외).
  시험 문제는 낱말 하나가 답을 가르므로 글자가 또렷해야 한다.
- **채점 안내문은 없다.** `틀렸습니다 — 내일 다시 나옵니다` 같은 줄을 두면 매 문제마다
  읽고 넘겨야 한다. 정답은 초록, 고른 오답은 빨강으로 칠하는 것으로 충분하다.
- 문제 본문은 **글(OCR)이 원본**이고, 교재 크롭은 `교재 원본 보기` 토글 뒤에 있다.
  크롭이 문제 경계를 정확히 못 잘라 옆 문제가 섞여 들어오기 때문이다. 그림이 필요한
  문제는 토글을 열어 본다.
- 문제를 노션에 추가했으면 **`fetch_problems.py` 를 다시 돌린 뒤** 빌드해야 반영된다.
  사이트는 정적 문서라 브라우저에서 노션 API 를 직접 부를 수 없다.

## 화면 넷 — 정리 · 암기 · 오답 · 설정

해시 하나로 오간다. 뒤로 가기가 그대로 먹으므로 폰에서 앱처럼 쓰인다.

**탭을 누르면 곧바로 카드/문제가 나온다.** 덱 요약(2주 표·통계·미리 보기)은 카드 위의
`N / M · 덱` 을 눌러 들어간다 — 매일 여는 곳이 카드인데 그 앞에 요약 화면을 한 장 두면
하루에 한 번씩 쓸데없이 더 누르게 되기 때문이다.

| 주소 | 화면 |
|---|---|
| `#note` (기본) | 과목 패널 6개 + 공부 패턴 타일 |
| `#s-xxxxxx` | 그 과목의 장·절 |
| `#memo` | **암기 카드 (오늘 몫)** — 암기노트 탭 |
| `#memo~` | 암기 덱 요약 (2주 표 · 통계 · 안 본 카드) |
| `#memo!7` · `#memo!new` | 제7장만 · 아직 안 본 카드만 |
| `#wrong` | **오답 문제** — 오답노트 탭 |
| `#wrong~` | 오답 덱 요약 |
| `#set` | 설정 (토큰 한 줄) |

- **오늘 자리가 비어도 카드가 나온다.** 주말이든, 배정된 장을 아직 안 썼든, 오늘 몫을
  끝냈든 — 그러면 **아직 한 번도 안 본 카드**로 흘러간다(카운터에 `· 안 본 카드` 가 붙는다).
  안내 화면을 한 장 두면 매일 그걸 지나쳐 누르게 되므로 두지 않았다.
- 그것까지 다 떨어지면 짧은 **`여기까지`** 판이 뜨고, 남은 것이 있으면 그리로 잇는 단추가
  하나 붙는다. 덱 요약을 다시 펼쳐 보이지는 않는다.
- **탭은 늘 보인다.** 탭이 곧 카드 화면이므로 감출 수 없다 — 감추면 갈아탈 길이 없어진다.
  채점 단추는 탭 위에 떠 있다. 탭 이름은 **`정리` · `암기` · `오답`** 한 줄이다.
- **과목 패널**은 끝이 둥근 직사각형 하나에 그 과목만의 **12주 히트맵**을 담는다.
  어느 과목을 며칠째 안 건드렸는지가 목록에서 바로 보이는 게 요점이다.
- 히트맵 칸은 **고정 10px** 이다. `1fr` 로 늘리면 폰에서 칸이 30px 이 되어 패널 하나가
  히트맵으로 꽉 찬다.
- 과목 화면 주소는 **ASCII 해시**(`s-<sha1[:6]>`). 한글을 주소에 넣으면 인코딩·NFC/NFD 에서
  어긋난다 — 파일명을 해시로 고정한 것과 같은 이유다.
- 안 쓴 단원은 **회색 '아직'** 으로 떠서 목록이 그대로 진도표가 된다(`SYLLABUS`, 231단원).
  장 제목은 노트 첫 줄(`# 제N장 …`)을 먼저 쓰고 비어 있으면 `SYLLABUS` 에서 채운다.
  단원 순서는 `## N.` 번호를 따른다 — **첫 두 줄의 번호를 빠뜨리면 목록에서 뒤로 밀린다.**
  목차 이름과 노트 제목은 괄호·공백·기호를 털어낸 뒤 맞춰본다(`_norm`). 새 노트를 썼는데
  '아직' 이 안 없어지면 두 이름이 너무 다른 것이니 한쪽을 맞춰주면 된다.
- **공부한 시간은 초시계가 없다.** 채점 시각 사이 간격을 더하고, 3분 넘게 벌어지면 끊고
  그 자리는 20초만 센다. 타이머를 새로 만들면 탭을 닫거나 폰이 잠길 때마다 어긋나므로,
  이미 있는 기록에서 되짚는 쪽이 튼튼하다.

## 기록은 어디에 있나

브라우저 **localStorage** (`j0-review-v1`) 하나. 암기·오답이 같은 저장소를 쓰고
**접두어로 가른다** — 암기 `m|<과목>/<단원>`, 오답 `p|<노션 페이지 id>`.
암기카드 신원이 단원 경로라서, 노트 본문을 고쳐도 그 절의 복습 이력은 살아남는다.

## PC ↔ 폰 자동으로 맞추기 (서버·DB 없음)

**누를 게 없다.** 깃 저장소의 파일 하나(`review-log.json`)를 두 기기가 공용 노트로 쓴다.
어느 저장소인지는 **빌드할 때 박힌다.** 고르는 순서는 `--repo` 플래그 → `build_review.py`
맨 위의 **`LOG_REPO` 상수** → `--out` 의 깃 remote(=사이트 저장소).
**바꿀 일이 있으면 플래그가 아니라 `LOG_REPO` 를 고쳐라** — 플래그를 한 번 빠뜨리면
저장소가 조용히 사이트 저장소로 돌아가고, 앱이 딴 곳을 보게 된다.
빌드 첫 줄에 어디로 잡혔는지 찍히고, 앱의 `설정` 화면에도 그대로 보인다. 언제 오가나:

- **앱을 열 때(새로고침)** — 목록이 받아서 합치고, 올릴 게 있으면 올린다
- **단원의 `학습완료`** — 그 자리에서 같은 일을 한 번 더
- 단원 페이지를 **열 때는 받기만** (2분 안에 이미 맞췄으면 건너뛴다)

올릴 게 없으면 커밋을 만들지 않는다. 앱을 여닫는 것만으로 이력이 더러워지지 않는다.

### 토큰 — 쓰기에만 필요하다

저장소가 공개라서 **읽기는 토큰 없이** 된다. 토큰을 안 넣은 기기는 자동으로
**읽기 전용**이 된다 — 진도는 보이지만 그 기기에서 채점한 것은 올라가지 않는다.
(브라우저에서 깃에 쓰려면 자격증명이 반드시 필요하다. 이걸 없앨 방법은 없다.
사이트 코드에 토큰을 박으면 GitHub 의 비밀 검사가 곧바로 폐기해 버린다.)

**한 번만 준비:**

1. github.com → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens** → Generate new token
   - Repository access: **Only select repositories** → 이 사이트 저장소 하나만
   - Permissions → Repository permissions → **Contents: Read and write**
   - 다른 권한은 주지 않는다.
2. 목록 화면 오른쪽 위 **`설정`** → 토큰 붙여넣고 `저장`.
3. 폰에는 주소 끝에 **`#t=<토큰>`** 을 붙여 한 번 열면 저장된다. 예:
   `https://<계정>.github.io/<저장소>/#t=github_pat_...`
   (그 주소는 남기지 말고, 저장된 뒤에는 `설정` 화면으로 넘어간다.)

토큰은 그 브라우저에만 저장되고 어디에도 올라가지 않는다. 기기를 잃어버리면 GitHub 에서
그 토큰만 폐기하면 되고, 권한이 저장소 하나뿐이므로 최악의 경우도 거기에 갇힌다.

### 알아둘 것

- 기록 파일이 **공개 저장소**에 있다면 그 내용도 공개다. 안에는 노트 내용이 없다 —
  카드 신원(단원 경로·노션 id), 날짜, 점수뿐이다. 그것도 싫으면 `--repo` 로 비공개 저장소를 쓴다.
- 합치기는 **양방향**이고, 같은 카드는 **복습 횟수가 많은 쪽**을 남긴다. 두 기기에서 같은 날
  공부해도 서로 지우지 않는다.
- 기록 저장소를 **사이트와 같은 저장소**로 두면 브라우저가 그 저장소를 직접 고치므로,
  사이트를 다시 올릴 때마다 로컬이 뒤처지고 `review-log.json` 에서 충돌이 난다.
  순서도 정해져 있다 — **커밋을 먼저, 그다음 `git pull --rebase`, 그다음 push.**
  (커밋 전에 pull 하면 `cannot pull with rebase: You have unstaged changes` 로 막힌다.)
  충돌이 나면 그 파일은 **원격 것을 쓴다**: `git checkout origin/main -- review-log.json`.
  기록 저장소를 **따로 두면** 이 골칫거리 전체가 사라진다 — 사이트 저장소는 내가 올릴 때만
  바뀌므로 그냥 push 하면 된다. 그래서 `LOG_REPO` 를 따로 두는 쪽을 권한다.
- 같은 저장소일 때 `review-log.json` 커밋마다 Pages 가 다시 배포되지만, 기록은 Pages 가
  아니라 GitHub API 로 읽으므로 배포가 늦어도 아무 영향이 없다.
- **기록 저장소를 비공개로 뒀다면 토큰 없는 기기는 읽지도 못한다.** 그럴 때 앱은
  "받지 못했습니다 — 기록 파일이 아직 없거나, 비공개 저장소라 토큰이 필요합니다" 라고
  말한다. 쓰는 기기마다 토큰을 넣어야 한다.
- 오류 문구는 원인을 그대로 알려준다: `401` 토큰 거부, `403` 권한 부족 또는 요청 초과,
  `GitHub 에 닿지 못했습니다` 는 인터넷/사내망 차단.
- 설정은 **토큰 한 줄뿐**이다. 하루 상한·파일 내보내기 같은 것은 두지 않는다 —
  덱 크기는 2주 사이클이 정하고, 기록 백업은 깃 이력이 맡는다.

## 폰에서 열기 — GitHub Pages

⚠ **`J_0` 전체를 올리면 안 된다.** 루트에 `.env` 와 `secrets/` 가 있어 자격증명이 새어 나간다.
**`study/site` 만** 따로 저장소로 만든다.

```powershell
cd study\site
git init
git add .
git commit -m "정리노트 복습 사이트"
gh repo create j0-review --public --source=. --push
gh api -X POST repos/:owner/j0-review/pages -f "source[branch]=main" -f "source[path]=/"
```

1~2분 뒤 `https://<계정>.github.io/j0-review/` 에서 열린다. 홈 화면에 추가하면 앱처럼 쓴다.

갱신 — **`git pull --rebase` 를 먼저** 해야 한다. 브라우저가 `review-log.json` 을
저장소에 직접 쓰고 있어서 로컬이 뒤처져 있다.

```powershell
py study\tools\build_review.py     # 어느 폴더에서 돌려도 된다
cd study\site
git pull --rebase                   # 기록을 같은 저장소에 둘 때만 필요
git add -A && git commit -m "갱신" && git push
```

> `--notes` / `--out` 기본값은 **스크립트 위치 기준**이라 `study\site` 안에서 돌려도
> 제 갈 길을 찾는다. (예전엔 현재 폴더 기준이라 `site\study\notes` 를 찾고 죽었다.)

> **사이트와 기록이 모두 공개된다.** Pages 는 무료 계정에서 공개 저장소만 띄울 수 있고,
> 복습 기록(`review-log.json`)도 같은 저장소에 있으니 함께 공개다. 기록에는 노트 내용이
> 없다(카드 신원·날짜·점수뿐). 노트가 인터넷에 놓이는 게 싫으면
> **Cloudflare Pages + Cloudflare Access** — 무료 범위에서 구글 로그인 뒤로 숨길 수 있다.
